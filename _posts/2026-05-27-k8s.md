# 사전 개념
## Pod
어플리케이션에서 컨테이너가 실제로 구동되는 가장 작은 배포 단위이다. 즉, 애플리케이션이 실제로 실행되는 곳.
네트워크 IP를 부여받고 실제 프로그램의 계산을 처리하지만, 스스로 죽고 사는 능력은 없다.

## ReplicaSet
파드의 수량을 모니터링하고 유지하는 컨트롤러이다. 파드가 항상 지정된 개수(replica)만큼 유지되도록 감시
예를 들어, "파드 3개 유지"가 조건이라면, 파드가 죽었을 때 새 파드를 생성해 수량을 맞춘다.

## Deployment
어플리케이션의 버전 관리 및 배포(Rolling update)를 총괄하는 오브젝트이다.
레플리카셋을 컨트롤하여 구버전 파드를 줄이고 신버전 파드를 늘리는 배포 전략을 실행한다.
예를 들어, 버전 1에서 2로 업데이트하면, 기존 레플리카 셋을 서서히 줄이고 새로운 레플리카 셋을 만들어낸다.

## Service
Deployment가 관리하는 파드 무리에게 단 하나의 고정된 진입점(IP/Port)을 제공하는 네트워크 단일 창구

# rolling update (배포) 과정
1. 배포 명령: 배포를 실행하면 Deployment가 변경 사항을 수정한다. (Deployment의 version=~~)
2. 새로운 ReplicaSet 생성: Deployment는 기존에 들고 있던 구버전 ReplicaSet을 건들지 않고 신버전(V2) 파드를 관리할 새로운 ReplicaSet을 만든다.
3. Rolling: 새 V2 ReplicaSet이 V2 파드를 먼저 하나(또는 지정된 개수 만큼) 띄운다. 파드가 생성되고 일할 준비가 되면 V1 ReplicaSet에게 V1 파드를 하나 죽이라고 명령
4. Service 트래픽 자동 전환: 배포가 진행되는 동안 Service는 실시간으로 파드 상태 감시. 만약 V1가 종료됐다면 그곳으로는 더이상 트래픽을 보내지 않음
5. 배포 완료: 교체 작업이 끝나면 V1 파드는 0개가 되고 V2파드는 목표 개수만큼 남는다. V1 replicaSet은 롤백을 위해 그대로 있는다.
